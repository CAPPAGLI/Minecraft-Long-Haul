# Transport Lab α1 — протокол проверки

## Итог

**Ограниченный серверный smoke/integration test пройден. Клиент и полная сборка по ТЗ не проверены и не завершены.**

Финальный результат `server-test/smoke-result.json`:

```json
{"ready":true,"exit_code":0,"timed_out":false,"integration_pass":true,"integration_fail":false,"clean_exit":true,"heap_mb":768,"client_tested":false}
```

Строки финального лога:

```text
LH_INTEGRATION_PASS: barrel extraction + timed model + persistentData + live adapter register/accept/tick/consume/receipt + advancement sync
The world border is currently 175000 block(s) wide
Saved the game
ThreadedAnvilChunkStorage: All dimensions are saved
```

Полный лог, результат и тестовый скрипт включены в архив исходников в `test-evidence/`. Тестовый скрипт **не включён** в `.mrpack`. Одна загрузка и короткая проверка не являются подтверждением стабильности на длительном сервере.

## Среда и объём

- Minecraft 1.20.1, Forge 47.4.10, Java 17.0.21, Linux x86_64, без графики.
- 62 внешних верхнеуровневых JAR в клиентском профиле; **51 внешний серверный + 1 собственный** JAR в серверном тесте. Клиентские файлы не запускались.
- Heap 768 MiB, metaspace 256 MiB, 2 видимых CPU — ограничения стенда, **не рекомендуемые параметры игрового клиента**. Пиковое потребление памяти корректно не измерено.
- Сохранённый плоский void/bedrock-мир `smoke-void`, не обычный Overworld с Terralith/Tectonic. Новая генерация обычного мира и дальние путешествия не проверены.
- В тестовом VS-конфиге: `synchronizePhysics=false`, `terrainBakingThreads=1`. Эти тестовые конфиги, свойства сервера, offline-mode и мир не распространяются в установочном архиве.
- Для теста бочка в чанке 0,0 принудительно загружалась; после успеха тестовый forceload снят. Рабочие контракты не загружают чанки принудительно.
- Выбор версий ограничен срезом **15.11.2026**. Логи стенда содержат дату 19.11.2026 из часов песочницы; это не дата среза и не основание выбирать более поздние версии.

| Загрузка выделенного сервера | Достигнуто `Done`, реально выполнены последующие проверки |

| Контейнер | Настоящая бочка: 27 слотов, запись 64 пластин, извлечение 16, остаток 48 |
| Модель окон | 12 отдельных Node-тестов; дополнительно модель трёх 60-секундных окон прогнана в Rhino. Это не 180 секунд наблюдения настоящего завода |
| Живой серверный адаптер | Регистрация пустой бочки и принятие `plates`; настоящий tick-handler изъял 64 пластины, завершил заказ и создал квитанцию с количеством 64; бочка опустела |

| Сохранение/выход | `save-all`, сохранены все измерения, код Java 0 без watchdog kill |
| Квестовые файлы | 26 валидных JSON, 3 группы; уникальные координаты, шаги 84×72. Отрисовка/центровка в GUI не проверены |

Тест advancement использует настоящий класс `ServerPlayer` без подключённого клиента, с пустым сетевым обработчиком от Forge FakePlayer. Сам Forge запрещает advancements для объекта класса `FakePlayer`, поэтому проверка на нём не подходит. Это headless integration fixture, **не** тест реального входа/сети/GUI. Регистрация бочки в тесте вызывает ту же функцию адаптера с объектом игрока-стендом; ввод `/lh` через настоящий клиент и путь Brigadier целиком ещё не проверены.

## Исправленные блокеры и ошибки стенда

1. Forge 47.4.0 не удовлетворял требованию Central Kitchen; закреплён **47.4.10**.
2. Extended Cogwheels 2.1.1 обращался к удалённым классам старого Create; исключён, а не скрыт флагом зависимости.
3. Clockwork 0.5.7 не давал нужный Kelvin в использованном графе; закреплён **0.5.6**, содержащий Kelvin 0.5.0.
4. Create Track Map 1.4 падал на запуске встроенного Ktor-сервера: `NoSuchMethodError` для `LockFreeLinkedListHead.addLast`. Исключён из lock/манифеста. Старый JAR в исследовательской папке не является частью пакета.
5. Серия ранних запусков останавливалась/убивалась при подготовке 441 чанка. Обнаружен и остановлен осиротевший процесс Java, который создавал дополнительную нагрузку. Точная первопричина всех ранних остановок не доказана.
6. Эксперименты ServerCore/Fastload не дали подтверждённого исправления; исключены вместе с ServerCore-конфигом. Long Haul Runtime согласованно уменьшает spawn ticket radius и ожидаемое число чанков до 2/9; загрузка после этого доходит до `Done`.
7. Искусственно включённая на стенде `synchronizePhysics=true` оставляла недемонический Physics thread после сохранения. Дамп подтвердил его ожидание; после возврата `false` несколько запусков завершились штатно. Это не исправление исходного кода VS и не проверка физики кораблей.
8. Исправлены ошибки **тестового** JS: вызов метода overworld как свойства; объявление функции внутри try в Rhino; `inventory.clear()` с выходом за индекс (подтверждено по байткоду KubeJS — заменён циклом допустимых слотов).
9. `scheduleInTicks` из loaded-event на уже сохранённом мире вызывал проверку на первом тике: внутренние часы планировщика ещё не совпадали со временем мира. Проверка перенесена в tick-handler после 60 тиков. Диагностика показала, что рабочая приёмка завершала заказ на 20-м тике; прежний ранний fail не был отказом рабочего адаптера.
10. Прямой FakePlayer не может получать advancements по явному ограничению Forge; у настоящего headless ServerPlayer без сетевой заглушки Heracles пытался отправить пакет в отсутствующее соединение. Стенд исправлен; эти искусственные игроки не включены в сборку.

## Оставшиеся предупреждения и риски

**Полный лог НЕ безошибочный.** В ранней стадии загрузки остаются сообщения `RuntimeDistCleaner` о клиентских классах и ошибка интерфейсного mixin Valkyrien Skies `feature.sculk.MixinVibrationSystemTicker` (непубличный метод). Они не остановили финальный запуск, но соответствующие ветки — в частности sculk/vibration и клиентский рендер — не проверены. Отсутствие ошибок в выводе команды KubeJS не отменяет ошибок других модов. Есть предупреждения VS о тегах материалов отсутствующих дополнительных модов.

## Что этот тест НЕ подтверждает

- Импорт `.mrpack` настоящим лаунчером; клиентский запуск, рендер, управление, FPS, карты и GUI Heracles.
- Сборку/движение поездов, летающих конструкций, Trackwork, столкновения, физику и сохранение кораблей.
- Генерацию обычного мира, совместимость всех структур/биомов, высотность и ресурсы внутри границы.
- Работу каждого из восьми контрактов в живом мире. Реально через tick-handler проверен **`plates`**; окна проверены моделью, а не полным длительным игровым испытанием.
- Реальное подключение/отключение игроков, восстановление задания после перезапуска, миграцию сохранений и командный прогресс. Проверен roundtrip данных в одном запуске, не полный restart/reconnect сценарий.
- Надёжность защит от всех способов перемещения/взрыва/доступа к терминалу; аудит всех переносных контейнеров.
- CC-программу на настоящем компьютере, снимки Exposure, голосовой чат и сеть между ПК.
- Производительность на ПК пользователя, multiplayer-нагрузку и многочасовой soak test.
- Реализацию восьми экономических городов, восстановления объектов, лагеря, всей кампании и цели примерно 500 модов.

**Решение:** выдавать только как `2.0-alpha.1 / Transport Lab`, с новым тестовым миром. Не объявлять стабильным релизом или выполнением полного ТЗ.
